A BOPTEST run survives a dropped connection, such as the Codespace port forward restarting:

- `BoptestPlant.step` recovers an advance that fails on the connection (no answer, or HTTP 502, 503 or 504), within 300 s of the failure (`RECOVERY_S`); it never guesses a state and never applies a step twice. An advance that never reached BOPTEST is resent. Any other is looked up in BOPTEST's stored results, since BOPTEST finishes an advance its client left: if they reach the step's end, the step's state is read back from them (`BoptestClient.state_at`); if they still stop at its start in an answer received 120 s (`ADVANCE_TIMEOUT_S`) after the advance was sent, it is resent. A step with no state by then fails with a message that says what was tried.
- Each recovered step is a warning and one more `PlantService.connection_recoveries`. `PlantProcessor` records it as a non-fatal error naming the run and the step, and a `plant_connection_recoveries` metric; it does not block the quote.
- `BoptestClient.stop` retries for up to 60 s (`STOP_RETRY_S`), and a test it cannot stop is logged with the command that stops it (`curl -X PUT <url>/stop/<testid>`). `BoptestPlant.stop()` waits up to 65 s (`STOP_WAIT_S`) for it. `BoptestClient` takes a `clock` and a `sleep`, and so does `BoptestPlant`.
- A transport error names the exception, and a timeout the seconds it allowed (`ReadTimeout after 120 s`), where httpx's empty message printed `ReadTimeout: `.
- A run that a fatal error ended is `failed` in its manifest (`RunManifest.ended`) and in `spotcool-world run`'s printout, as in its `run_status` event; `cancelled` is left for a run stopped from outside, such as by Ctrl+C.
- The BMS reports, once, a non-fatal error when the PC no longer has the address it bound ("the PC's network changed: the BMS at <ip>:<port> is unreachable; restart the run on one network"); the run goes on.
- `AGENTS.md` gives the supervised port-forward loop and the rule that the PC stays on one network for the whole run, with the `netsh` command that keeps Windows from switching networks.
