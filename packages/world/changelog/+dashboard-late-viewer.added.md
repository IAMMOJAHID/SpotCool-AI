The dashboard feed catches a late viewer up: `/ws/events` sends each new client the current run's events so far, then the live ones, each once and in order (`EventFeed`). The history keeps the latest `vrf_state` and the latest of each metric, starts afresh at a new run, and holds at most 50,000 events. The camera and calendar server's CORS also lets the dashboard's own page read it when that page is served from a loopback, RFC 1918 or link-local address (`create_http_app(..., dashboard_port=...)`), so a dashboard opened from another PC on the LAN shows the cameras.
