Telemetry, KPIs, the run recorder, the dashboard feed and the run report (WP6):

- `TelemetryProcessor` fills each `PlantMeasurementsFrame.summary` through the office BMS point map: every zone in BMS units, the seven HVAC meters in kW by point name (BOPTEST's ElectricPower basis), their total, and the run's cumulative energy by the trapezoid rule from its first frame with the meters (`metered_summary`, `summarize`, `power_kw`, `EnergyMeter`). A frame lacking a value (BOPTEST's nulls, such as an initial state's setpoints) gets no summary and is logged once; the KPIs and the report skip it.
- `KpiProcessor` scores both runs at each tick: comfort where people were (K h; the people of the step that just ended, the baseline's applied setpoints as the band, the same for both runs) and energy saved (%, at the same stamp). It pushes a provisional `KpiFrame` per run every 4 steps, and at the first end frame one final `KpiFrame` per run that merges the plant's BOPTEST KPIs.
- `EventEmitterProcessor` turns every domain frame into its contract event ahead of the frame (`frame_events`): a complaint cue's audio file name never reaches an envelope, metrics go one event per sample, and the `tick` event closes each step. `EVENTS_TOPIC` names the one event stream.
- `RecorderProcessor` writes `runs/<run_id>/events.jsonl` (every envelope on the events topic, the occupant worker's and the agent's included, and every plant state as a raw record that `ReplayPlant` replays) in pipeline order, flushed once per tick by a background task, and `manifest.json` (`RunManifest`: settings with secrets redacted, URL credentials and secret query parameters included, git sha, versions, scenario sha256, final KPIs, `dropped_events`). The first end or cancel finishes the record as one shielded task, so a `stop()` as the run ends neither loses events nor leaves the file open. Recording failures are fatal; an existing record is never appended to; run ids must match `RUN_ID_PATTERN`.
- `create_dashboard_app(bus, run_dir, dist_dir)` (extra `dashboard`): `/ws/events` broadcasts the stream with a bounded drop-oldest queue per client; `/ws/agent` publishes the agent's perception, decision, explanation and chat events after checking JSON, envelope, source, type, size (64 KB), rate (20 a second) and that they carry no image (no `data:` string, none over 8192 characters), refuses browser pages from other origins, and never sends world events; `GET /runs`, `GET /runs/{run_id}/events.jsonl` with a path guard, `/healthz`, and the built dashboard at `/`.
- `spotcool-world report <run_id>` (extra `report`, matplotlib): `report.md` with the KPI table, recovery times after each arrival (and the arrivals that never recovered) and the honesty note, plus power and energy, zone temperature and occupancy charts.
- Example `09_record_and_report.py`: the hybrid Tuesday on two RC plants, recorded and reported in seconds.
